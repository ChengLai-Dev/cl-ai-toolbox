## 审查对象

程序工程目录：代码、场景、配置文件、构建脚本、工程说明与 HANDOFF。

## 必读

- `docs/PROJECT.md`（项目定位）
- `docs/contracts/data.md`（数据契约，注意版本号）
- `docs/contracts/assets.md`（素材技术规格）
- 派活指定的策划案与工程说明 / HANDOFF

## 审查维度

1. **能跑**：工程可打开可运行、无致命报错；静态检查或构建自检通过。
2. **能玩**：核心循环闭环，改动有可见可操作的即时反馈；无卡死、无软锁。
3. **逻辑与边界**：0、负数、溢出、空关卡、重复触发、存档读写异常路径是否处理。
4. **与契约一致**：配置字段名逐一比对 `data.md` 的字段名列；数值照搬未走样、未被擅自改动；状态键与契约状态名一致；素材接入的锚点、朝向、帧率与 `assets.md` 一致。
5. **结构**：目录按功能划分、命名遵循所用语言/框架的官方风格；无未声明依赖、无死代码残留。
6. **手感**：输入响应、动画缓动、打击反馈、震动是否做了。缺失归「建议」，明显迟钝归「严重」。
7. **数据驱动**：数值、关卡、掉落是否独立成配置；逻辑里有没有硬编码数值。

## 阻断判据

跑不起来、核心循环断、字段名与契约对不上、数值走样、素材规格与 `assets.md` 不符 —— 任一即阻断。

## 自检

按工程说明能复现运行吗？字段名与契约逐条对过了吗？边界情况都试算过吗？报告写到指定路径了吗？
