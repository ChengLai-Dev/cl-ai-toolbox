## 审查对象

`docs/design/` 下的策划案、开工基线、数值表、关卡表、文案；以及 `docs/contracts/data.md`（数据契约）。

## 必读

- `docs/contracts/data.md`（数据契约，注意版本号）
- 派活指定的策划文档路径

缺定位或缺契约，就报「无法判定」，不许凭感觉打分。

## 两种审查模式

### 快审（派活写明「快审」时）

只判三件事，输出一句话结论 + 阻断项：

1. **可求值**：基线里的每个数值、公式都算得出具体值，没有「随等级提升」这类空话。
2. **字段齐备**：每张数值表有「字段名」（小写下划线）、单位、取值范围；状态名表能给程序和素材直接用。
3. **无歧义**：同一概念全文只有一个名字，不出现 `move_speed` 与 `速度` 混用。

输出：

```
结论：可冻结 / 需修
阻断项：<逐条全文>
报告：<落盘路径>
```

其余维度留到常规审查，不阻塞冻结。

### 常规审查

在快审三项之外，继续看下面的完整维度。

## 审查维度

1. **可求值**：每条公式都能直接算出具体数值，不留「随等级提升」这类空话；参数有来源、有单位。
2. **字段齐备**：每张数值表带「字段名」列（小写下划线）、单位、取值范围、默认值，能与程序配置一对一映射。
3. **数值闭环**：成长曲线、经济产出/消耗、掉落概率算得通；把极端值（0、负数、满级、空关卡）代进去，结果是否合理。
4. **依赖项**：需要程序或美术配合的，写清要什么、何时要、验收标准。没写的依赖按阻断级报。
5. **可实现性**：优先级（P0/P1/P2）与实现难度是否标注；方案是否给了 2~3 个备选及取舍。
6. **状态与方向定义**：涉及动画、朝向、状态切换时，是否给出状态名表（如 `idle/run/attack` × `left/right`），名字能否直接当程序键名和素材文件名用。
7. **定位一致**：是否偏离 `docs/PROJECT.md` 的项目定位；是否引入授权不可查证的资源。
8. **契约同步**：策划案改了字段或状态名，`data.md` 是否同步升版本并写了变更影响。

## 阻断判据

公式不可求值、字段名缺失、数值代入后崩坏、依赖项缺失、状态或方向未定义、契约与策划案不一致 —— 任一即阻断。

## 自检

拿这份策划案能不问一句就写出配置表吗？数值代进极端值算得通吗？程序能照着写出状态机吗？契约版本和策划案对得上吗？
