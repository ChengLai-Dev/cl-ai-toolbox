# 图像线实测细节与口径说明

本文是 `game-art-image` 的支撑材料。数据来自 2026-11-01 的本地复测：**55 张（FLUX 28 / MOSS 27）**，
同 prompt、同 seed、同分辨率、同参数档。原始图与逐张账本在 `D:\Code\dsh-workspace\Experiment\bench\`。

## 一、测过的环境

| 项 | 值 |
|---|---|
| GPU | RTX 5060 **8GB** / 32GB RAM / Windows 11 |
| 显存基线 | 1.8 GB（关掉 UnrealEditor 后） |
| 后端 | ComfyUI 0.43.0 + torch 2.11.0+cu128，独立 venv |
| FLUX 量化 | DiT int8-convrot + Qwen3-VL-4B int8 + VAE fp16 |
| MOSS 量化 | DiT int8-convrot + Qwen3.5-9B w4a8-gptq + VAE small |

**torch 是 cu128 不是 cu130**：`comfy_kitchen` 的 int8 kernel 被禁用，退回 eager 实现。
耗时因此偏慢，画质不受影响。换 cu130 可能提速，但会破坏与本表数据的可比性。

## 二、关键指标怎么算的（口径很重要）

### 背景纯净度：四角标准差

取图像四角各 12% 区域，算 RGB 标准差再平均。**值越低越接近纯色底**。

实测值：干净底 0.5–2.0；画进了内容 > 6；等距地块类 14–19（含纹理本身）。

### 棋盘格：背景区 FFT 周期峰

对右下角 18% 区域做 FFT，去掉直流分量后取最大峰 / 均值。**规则棋盘格会出强周期峰。**

实测：正常图 15–137，棋盘格图 160–234。这个指标能抓到肉眼在浅灰底上漏看的伪影。

### 锐度：拉普拉斯方差

3×3 拉普拉斯核卷积后取方差。**值越高细节越多。**

实测：金冠特写 FLUX 2820 vs MOSS 2069（1.36×）；短剑特写 FLUX 376.6 vs MOSS 97.2（**3.87×**）。

### 像素画纯度：零差分比例

相邻像素完全相同的比例。**注意：高不代表是像素画，只说明平坦色块多。**

实测 FLUX 0.037–0.275，MOSS 0.248–0.454。MOSS 更高是因为它色块更整，
但它的像素网格并不比 FLUX 严格。**这个指标不建议单独引用。**

### 一致性：颜色直方图距离

16³ bin 的 RGB 直方图交集距离，四视图两两配对取均值。**越低越一致。**

实测：FLUX 0.7653 / MOSS 0.5128。**但本轮不建议采信这个结论**——原因见下节。

## 三、三个不能直接采信的结论

### 1. 一致性数值优势可能是假象

MOSS 把 `character sheet` 按字面理解，输出了三视图（画面里有 3 个角色），
颜色分布被「填满」，反而压低了与其他三张的直方图距离。

**肉眼看**：FLUX 四张的斗篷绿、发色、靴色逐张一致；MOSS 的发色在 `cons-left` 偏橙、`cons-right` 偏红，有漂移。

**结论**：以肉眼为准，本项判 FLUX 略优，MOSS 的量化优势不计入。

### 2. 上采样器消融不是模型对比

MOSS 上采样器的 system prompt 明确要求「以 Studio photograph of… 开头、加细节」，
它实际在**替你重写提示词**。所以开/关是**两个不同的提示词**，不是同一输入的两个渲染。

数据本身有效（118s → 426s，画面更干净、不加装饰），但只能当**流程对比**看。

### 3. FLUX 的 alpha 消融说明参数无效

同 seed、同 prompt，`alpha=16`（μ=2.7726）vs 默认（μ=1.93586）：耗时 33.1s vs 36.7s，
画面肉眼无法区分，仅刀尖角度差几度。

**这个「无差别」本身就是结论**：该参数不是杠杆，不必花时间调。

## 四、逐用例背景数据

| 用例 | FLUX std | MOSS std | FLUX 峰 | MOSS 峰 |

| prop-anime | 0.60 | 0.70 | 16.8 | 29.9 |
| prop-pixel | 0.57 | 0.61 | 24.6 | 30.1 |
| prop-isometric | 0.55 | **6.19** | 14.7 | **178.9** ⚠️ |

⚠️ 标记的三张就是棋盘格伪影。**注意只有 3 张**——旧报告说「在 3 个不同用例中重复出现」，
方向对，但范围比「MOSS 不适合做纯色底资产」这种一刀切结论要窄得多。

`text-en` 的 MOSS 27.90 是因为画面边缘有装饰性木纹，不是伪影。

## 五、本轮相对旧基线的三处修正

| 项 | 旧基线（2026-10-30） | 本轮 | 为什么改 |
|---|---|---|---|
| FLUX shift | `alpha=16`（BFL 版） | 模型内置 μ=ln(6.93) | ComfyUI 模板子图里**没有** `ModelSamplingFlux` 节点，内置才是出厂默认 |
| MOSS 负向提示 | 空字符串 | 官方默认负向 | 旧基线与模板不一致 |
| 显示基线显存 | 2.2 GB | 1.8 GB | 关掉 UnrealEditor 后实测 |

## 六、未做的事（结论的边界）

| 未做 | 影响 |
|---|---|
| bf16 对照 | 结论限定在 int8 档 |
| 4K / 2048 极限分辨率 | 极限性能未测（旧基线有，可参考） |
| MOSS 50 步模型卡档 | 未验证 25 步是否牺牲质量 |
| 接抠图模型评估「可抠性」 | 棋盘格对 alpha 通道的实际破坏未量化 |
| 一致性 3 动作 × 4 朝向全量 | 本轮只做 1 动作 × 4 朝向 |

**最有价值的下一步**：接 BiRefNet 实测棋盘格对抠图的真实危害。目前只知道有伪影，
不知道它到底会让抠图失败到什么程度。

