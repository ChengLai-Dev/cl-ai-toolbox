# 游戏美术资产生产

本技能是把「策划要一个资产」变成「引擎里能用的文件」的流程总控。四条流水线各自独立，先按资产类型路由。

## 路由表

四个子技能与本技能同处 `game-art-assets\` 下（`image\` / `model\` / `video\` / `audio\`），按需加载对应子技能。

| 要做的资产 | 子技能 | 本机状态 |
|---|---|---|
| 静态图：道具 / 图标 / 立绘 / 地块 / 场景背景 | `game-art-image` | ✅ 已部署，实测 55 张 |
| 3D 模型：道具 / 场景件 / 武器 / 角色（导入 UE） | `game-art-model` | ✅ 已部署，单图约 2 分/件，已导入 6 件 |
| 3D 角色 / 怪物（**需要骨骼动画**） | `game-art-model` 的 RIGGED 分支 | ✅ 已验证：poly.pizza 直链 → Blender 转换 → UE 体检 |
| 动态画面：过场 / 特效 / 循环动作 / 宣传片 | `game-art-video` | ✅ 已部署，实测通过 |
| 声音：音效 / 环境音 / BGM | `game-art-audio` | ✅ 已部署，音效 50 步约 12 分钟/条，180 秒 BGM 约 50 秒 |

判断顺序：

```
要动的吗？要摆进 3D 场景吗？
├─ 不动的静态画面（UI/图标/氛围图）→ game-art-image
├─ 要摆进 3D 场景的实体 → game-art-model
│   └─ 需要骨骼动画（人形/怪物走路攻击）→ game-art-model 的 RIGGED 分支（现成资产转换）
├─ 要动的画面
│   ├─ 逐帧角色动画（walk/run/attack 循环）→ 先 game-art-image 出单帧，再交视频线或手绘补帧
│   └─ 过场/特效/镜头运动 → game-art-video
└─ 出声的 → game-art-audio
```

**最容易走错的两步**：
- 把「角色行走循环」直接丢给视频模型——视频模型出的是连续视频，不是逐帧对齐的序列帧。
- 把 3D 模型当图片资产做——模型线要额外过 UE 导入，且不能直接产出 uasset。

## 通用铁律

这几条对四条线都成立，违反任何一条产出的素材都进不了引擎。

1. **先定规格再出图**。画布尺寸、朝向、锚点、透明底要求、命名，必须在出第一张之前定死。出完再改规格等于重做。
2. **一次只验一个变量**。同 seed、同提示词，只换模型或只换参数。混着改，出了好图也不知道该复现哪个。
3. **每张图都要有账本**。prompt / seed / 步数 / CFG / 采样器 / 耗时 / 峰值显存，写进同名 `.json`。没有账本的图不可复现，等于一次性素材。
4. **交付前必须过校验**。尺寸、透明通道、锚点、像素网格对齐——肉眼看着对不等于引擎里对。
5. **许可证先查再用**。各家的许可差异是实质性的，见各子技能的许可小节。

## 显存前提（8GB 卡）

四条线共用一个物理约束：本机是 **RTX 5060 8GB**，实测空载桌面占用约 1.8–2.3 GB，留给模型的只有约 5.9 GB。

- **同一时刻只能跑一条流水线的模型**。图像 / 模型 / 视频不能同时驻留，切换必须先卸干净。
- 起服务前查显存：`nvidia-smi --query-gpu=memory.used --format=csv,noheader`
- 开了 UnrealEditor / 大型游戏 / 录屏，显存会被吃掉 3–5 GB，模型必 OOM。**先关再跑**。
- 判据：显存占用低于总显存 55%（约 4483 MiB）才算释放干净。

## 交付形态

| 资产类型 | 交付物 | 注意 |
|---|---|---|
| 静态图 | `png` + 同名 `json` 账本 | 需要透明底的必须验 alpha 通道 |
| 序列帧 | `atlas.png` + `manifest.json` + `frames/` | manifest 要有 fps / 朝向 / 锚点 / 循环标记 |
| 3D 模型 | `.glb` 源（放工程外）+ UE `.uasset` | uasset 只能由 UE 导入生成；导入后拍平目录并开 Nanite |
| 视频 | `mp4`（h264 + aac） | 过场要标明是否带音轨 |
| 音频 | 音效 `wav`（48kHz 单声道 / PCM_16）；BGM `flac`（48kHz 立体声） | 标明是否循环；交付前跑 `check_audio.py --transient` |

## 反模式

- ❌ **只出一个模型就下结论**。本机有两个生图模型且强弱项互补，单模型出图会在某类资产上系统性吃亏。
- ❌ **拿视频模型的输出当序列帧用**。帧数、循环闭合、像素对齐都不满足。
- ❌ **跳过账本**。调参调出好结果却记不住参数，是这条流水线最常见的时间浪费。
- ❌ **在 8GB 卡上同时开图像 / 模型 / 视频服务**。必然 OOM，且 OOM 后显存可能不释放，要重启进程。
- ❌ **把 `.glb` 放进 `Content\` 等 UE 自动识别**。它不是资产，必须走导入。
- ❌ **用四视图回灌去补背面**。输入来自同一网格，信息量不变，只是更规整、耗时翻三倍。
