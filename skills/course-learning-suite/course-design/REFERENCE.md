# 参考规范

## 课程包文件结构（文档式 / 混合式）

```
<课程根目录>/
├── COURSE.md          # 课程信息、章节总览表、学习路径建议
├── PROGRESS.md        # 进度追踪表、复习记录
├── chapters/          # 章节讲义：01-<章节名>.md、02-<章节名>.md ...
└── quizzes/           # 章节测验：01-<章节名>.md、02-<章节名>.md ...（与讲义一一对应）
```

### 讲义格式（chapters/NN-<名称>.md）

```
# NN <章节名>

> 本章目标：<学完本章能做什么>
> 预估学习时间：<X> 分钟

## <小节 1 标题>

<概念讲解，先概念后示例>

### 示例

```<语言/代码块>
<示例代码或演示>
```

**要点**：
- <要点>

## 本章小结

- <小结 1-3 条>

## 本章自测

完成测验：见 `../quizzes/NN-<章节名>.md`，做完后对照答案自评。
```

### 测验格式（quizzes/NN-<名称>.md）

- 混合题型：选择题 + 简答题 + 动手/代码题，难度递进，单章 5~10 题
- 按 Bloom 六层出题（见下节），L1-L3 基础必保，L4-L6 视用户水平酌量
- 答案统一放文档底部 `## 答案` 区域，用引用块与题目分隔，标注"先作答再对照"

### PROGRESS.md 进度表格式

```markdown
## 章节状态

| 章节 | 名称 | 状态 | 完成日期 | 备注 |
|------|------|------|---------|------|
| 01 | <名称> | [ ] 未学 | - | |
```

- 用户学完某章告知后：更新状态为「已完成」+ 完成日期，记录薄弱点备注
- 混合式每次会话开始时先读 PROGRESS.md 恢复，会话结束更新；不依赖对话记忆

## 三种输出模式

### 聊天交互式

- 不写任何文件，全程对话推进
- 先输出学习路径（阶段→章节树状图 + 时间分配），再讲当日一个章节
- 每章按 Phase 3 推进，进度靠对话上下文维持（用户可随时要求转为混合式落盘）

### 完整课程文档

- 一次性生成全部文件：COURSE.md + 全部 chapters/ + 全部 quizzes/ + PROGRESS.md（预置"未开始"）
- 遵循自洽性原则：所有测验引用的概念必须在对应讲义讲解中出现
- 交付后不进入交互推进；用户想恢复交互学习时可发起新模式

### 混合式

1. 首先生成：COURSE.md + PROGRESS.md（进度表）
2. 每学完一个章节：用户反馈练习结果（口头或文字，描述关键结论即可）
3. AI 对照章节目标检查理解、纠正错误、判定掌握度（优/良/差，标准见下节）
4. 掌握度与薄弱点写入 PROGRESS.md
5. 根据掌握度决定下一章节详略，然后生成下一章节讲义 + 测验
6. 复习点到达时（用户设定的间隔或 AI 建议），用 PROGRESS.md 生成针对性回顾问题

## Bloom 分层出题

| 层次 | 类型 | 示例问题 |
|------|------|---------|
| L1 - 记忆 | 概念复述 | "[概念]的定义是什么？" |
| L2 - 理解 | 用自己的话解释 | "说明[概念]的工作原理" |
| L3 - 应用 | 在场景中使用 | "在[场景]中如何使用[概念]？" |
| L4 - 分析 | 比较和对比 | "[概念A]和[概念B]的区别？" |
| L5 - 评价 | 判断优劣 | "在[约束]下，哪种方案更好？" |
| L6 - 创造 | 独立产出 | "用所学知识实现一个[项目]" |

出题原则：

- L1-L3 为基础，每章至少保证；L4-L6 视用户水平酌量
- 分层递进：前一层题目是后一层的铺垫，不跳层
- 题目必须能验证章节的学习目标，不考目标外内容

## 学习者状态跟踪与动态调整

| 掌握度 | 表现特征 | 调整策略 |
|--------|---------|---------|
| 优 | 能自主总结、练习一次通过 | 保持节奏，可加 L4+ 题目或拓展内容 |
| 良 | 总结有遗漏、练习需少量提示 | 正常推进，下一章开头回顾薄弱点 |
| 差 | 总结含糊、练习大量错误 | 放慢节奏，补充讲解与示例，暂缓新章节 |

调整原则：

- 以学习者实际表现调整，不按计划硬推
- 深度不够 → 加深追问；进度落后 → 压缩次要章节，保住核心章节
- 状态落盘：混合式每次会话结束前把掌握度、薄弱点写入 PROGRESS.md

## 自洽性原则（关键）

- 讲解内容必须足够详实，使得学习者仅凭刚讲的内容就能回答测验和完成任务
- 测验中提到的所有概念、语法、API 必须在对应讲义中有明确交代
- 出完测验后自查一遍：每个测验引用的知识点是否都已在讲义中出现
