# Course Design

## Quick start

1. **收集信息**：按下方清单问全 8 项，缺一不可
2. **设计课程**：按 Phase 1 确认的输出模式产出（模式细节见 [REFERENCE.md](REFERENCE.md)）
3. **推进课程**：交互式/混合式按掌握度动态调整（见 Phase 3）

## Phase 1：信息收集

用户提出学习需求后，**必须**先询问以下信息才能开始设计课程，未集齐前禁止生成课程内容：

| 问题 | 目的 |
|------|------|
| 你想学习什么主题/学科？ | 明确学习内容 |
| 你当前的 level 是什么？（完全新手 / 有基础概念 / 有一定实践经验 / 熟练） | 确定起点 |
| 你的学习目标是什么？（了解 / 掌握 / 精通） | 确定终点 |
| 你希望的学习周期是多久？（几天 / 几周 / 几个月） | 确定节奏 |
| 你每天大概能投入多少时间？ | 确定单次容量 |
| 你更偏好理论先行还是实践驱动？ | 确定路径方向 |
| 是否有需要用到的具体项目场景或工具版本？ | 确定上下文 |
| 你希望以什么形式产出课程？产出形式和文档格式？ | 确定输出模式 |

## Phase 2：课程设计

按 Phase 1 确认的**输出模式**产出，共三种：

- **聊天交互式**：输出学习路径 + 当日所需章节（一次一个），随后进入 Phase 3 交互推进。适合基础薄弱、需要陪伴纠偏的学习者
- **完整课程文档**：一次性生成完整课程包（COURSE.md + 全部 chapters/ + 全部 quizzes/ + PROGRESS.md），以 Markdown 文件写入目录；产出后**不再**进入 Phase 3，用户对照文档自学。适合基础较好、自律的学习者
- **混合式**（文档沉淀 + 交互推进）：先产出 COURSE.md + PROGRESS.md，再**逐章节生成**讲义与测验；用户完成练习后反馈结果，AI 检查理解、纠正错误、更新进度，再生成下一章节。适合想要文档沉淀又需要纠偏的学习者。若用户选文档产出，优先推荐此模式，但必须让用户知情选择

输出模式不互斥，学习过程中可随时切换（如文档模式中途想转混合式）。

### 课程包文件结构（文档式 / 混合式）

```
<课程根目录>/
├── COURSE.md          # 大纲：课程信息+章节表+学习路径建议
├── PROGRESS.md        # 学习进度清单（章节状态+完成日期）
├── chapters/          # 章节讲义（01-<名称>.md 起，NN- 数字前缀）
└── quizzes/           # 带答案测验（与章节一一对应）
```

讲义与测验格式规范见 [REFERENCE.md](REFERENCE.md)。

## Phase 3：交互推进（交互式 / 混合式模式）

每次完成一个章节后按序执行：

1. **引导输出**：让用户用自己的话总结刚学的内容（费曼技巧，先听后讲）
2. **检查理解**：按 insight-check 的规则执行——先判断见解质量（定义含糊/概念混淆/以偏概全/明显错误），再按规则 A（纠正+追问）或规则 B（肯定+可选延伸）响应，掌握度换算后写入 PROGRESS.md
3. **间隔重复**：随机插入 1-2 个之前章节的复习问题
4. **动态调整**：按掌握度（优/良/差）调整后续内容的深度与节奏，不按计划硬推

掌握度判断与调整策略见 [REFERENCE.md](REFERENCE.md)。

## 关键原则

- **自洽性**：讲解必须详实到仅凭讲解内容就能完成练习，禁止"讲了没考、考了没讲"
- **单次容量**（交互式/混合式）：一次只产出一个章节，不一次性给出全部内容
- **认知负荷**：单章核心概念 3-5 个；测验题 2-3 组且难度递进
- **知识来源**：模型自身知识 + 用户提供的资料；资料与讲义冲突时以资料为准并标注差异；不主动联网，除非用户要求；不确定的知识点标注「待考证」
