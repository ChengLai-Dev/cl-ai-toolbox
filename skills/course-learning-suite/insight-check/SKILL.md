# 交互式概念学习

通过苏格拉底式追问帮助用户深化对概念的理解。

## 核心逻辑

用户陈述见解后，先按**判断标准**归类，再决定响应方式。

### 规则 A：见解不具体或存在明显错误

1. **展开或纠正**：补充缺失的关键维度，或纠正错误理解
2. **追问**：列 1-3 个探测性问题（从浅到深，聚焦用户刚才缺失/含糊的维度）
3. **进入追问循环**：用户回答后评估并决定深入或收敛（机制见 [REFERENCE.md](REFERENCE.md)）

### 规则 B：见解已较深刻、无明显错误

1. **肯定用户的见解**：具体指出对在哪里，不空洞夸奖
2. **可选延伸**：若存在值得深挖的下一层，用一句话点出并询问意愿；用户无意向则不再追问

## 见解质量判断标准

满足以下任一条件 → 规则 A：

| 信号 | 表现 |
|------|------|
| 定义含糊 | 只给例子或表现，未触及本质（如"多态就是子类重写父类的方法"） |
| 概念混淆 | 混淆相邻概念（如把重写当重载、把指针当引用） |
| 以偏概全 | 只覆盖概念的一部分，缺失关键维度（如只说运行时多态） |
| 明显错误 | 事实性错误或逻辑矛盾 |

反之：定义准确、覆盖主要维度、无明显错误 → 规则 B。

## 响应模板

### 规则 A 模板

```
[展开或纠正用户见解的内容...]

---

如果你愿意进一步探讨，以下问题可以帮助加深理解：

1. [问题1]
2. [问题2]
3. [问题3]
```

"展开或纠正"部分按固定顺序组织（不要只抛结论）：

1. **指出错误/缺口**：具体指出哪句话不对、哪个维度缺失（引用户原话，不笼统说"理解有误"）
2. **给出正确概念**：用精确语言讲清楚正确理解
3. **示例或对照**：给代码/场景示例，或对照用户已知的相邻概念支撑理解；**不使用引入额外领域知识的生活类比**

### 规则 B 模板

```
[肯定用户的见解，具体指出正确之处]
```

## 追问原则

- **数量控制**：一次最多 3 个问题，避免认知负荷；根据用户回答再继续
- **层次递进**：先问定义边界，再问机制原理，最后到应用与反思（5 层设计见 [REFERENCE.md](REFERENCE.md)）
- **聚焦薄弱**：优先追问用户表述中缺失或含糊的维度，不做全面轰炸
- **衔接**：追问中暴露出系统性知识缺口时，建议用户发起课程设计补齐

## 与 course-design 的掌握度换算

交互过程中持续记录用户表现，换算出课程推进所需的掌握度（优/良/差）：

| insight-check 表现 | 掌握度 | 课程推进策略 |
|--------------------|--------|--------------|
| 定义准确、覆盖主要维度、能自主举例 | 优 | 保持节奏，可加 L4+ 题目 |
| 有遗漏或模糊，追问 1-2 次后能补上 | 良 | 正常推进，下一章开头回顾薄弱点 |
| 连续降层追问仍答不上（REFERENCE.md 多轮追问循环第 3 条） | 差 | 放慢节奏，补充讲解，暂缓新章节 |

换算结果写入课程进度文件 PROGRESS.md（见 course-design REFERENCE.md 进度表），保证跨 skill 协作口径一致。
