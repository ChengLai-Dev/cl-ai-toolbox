# 参考规范

## 探测问题 5 层设计

追问问题按以下层次从浅到深递进，**每次从用户暴露的薄弱维度切入**：

| 层次 | 目的 | 示例 |
|------|------|------|
| L1 定义边界 | 概念是什么、不是什么 | "多态包含哪几种？运行时多态和编译时多态分界在哪？" |
| L2 机制原理 | 为什么、底层怎么运作 | "虚函数调用在底层走什么路径？" |
| L3 关联关系 | 与相邻概念的关系 | "override 和 overload 在哪些场景会同时出现？" |
| L4 应用推演 | 在场景中会怎样 | "如果去掉 virtual，下面这段代码输出什么？" |
| L5 批判反思 | 何时不适用、有何代价 | "虚函数表方案有什么性能代价？什么场景下该避免？" |

原则：

- 不必每轮都从 L1 开始，按用户表述缺口定位起始层
- 同一轮最多跨 2 层，跳层追问容易造成认知负荷

## 多轮追问循环

1. 用户陈述见解 → 按判断标准归类（规则 A / 规则 B）
2. 规则 A：纠正 + 抛 1-3 个探测问题
3. 用户回答后**重新评估**：
   - 回答准确 → 肯定 + 可进入下一层或收敛
   - 回答仍有缺口 → 降一层追问（L2 → L1），聚焦更小的点
   - **连续 2 次降层仍答不上** → 停止追问，给出完整讲解，记录为掌握度「差」
4. 收敛条件：用户答上当前层 + 基本层（L1/L2）无缺口，即可结束本轮

## 与 course-design 的协作约定

- course-design 的 Phase 3「检查理解」环节按本 skill 规则执行：先让用户完整陈述，再判断质量
- 用户在学习中主动陈述自己对某概念的理解时，按本 skill 规则响应，教学推进暂时让位
- 探测问题参考 5 层设计（定义边界 → 机制原理 → 关联关系 → 应用推演 → 批判反思）
- 掌握度换算结果写入课程 PROGRESS.md 进度表，字段：掌握度（优/良/差）、薄弱点
- 用户暴露出系统性知识缺口（连续追问失败）时，引导其发起新的课程设计补齐基础
