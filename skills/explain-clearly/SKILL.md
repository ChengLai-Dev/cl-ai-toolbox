# 清晰讲解技能

## 这个技能真正要求的是什么

你不是在套一段固定话术，而是在换位思考：**假设自己完全不懂，只靠眼前这段文字，能不能一步步推下去、不产生疑问。**

讲解有两个轴，本技能两个都要：

- **顺**：读者能跟上，不靠猜。
- **透**：读者能带走一个判断依据，下次自己用得上。

只做到"顺"，交付的是**答案的正确性汇报**——读者知道了"这样对、那样错"，但不知道"凭什么"，换一道题还是不会。这种情况下的典型反馈是"讲了也没用""没汲取到营养"。

### 内核意图（表达层）

怎么表达由你自己决定，只要读者能跟上：

1. **指代不含糊**：凡是提到某个东西，读者必须能明确知道指的是哪一个，不需要回头猜。代码/文件/位置尽量锚定到具体内容。
2. **思维不跳跃**：结论不是从天而降的。在抛出结论前，让读者先拿到它成立所需的材料；中间被省略的那一步，往往正是读者卡住的地方。
3. **抽象落地**：遇到术语或概括性的说法，别换个词重复一遍，要展开成"具体会发生什么、为什么"。
4. **引导思考，而不是下结论**：让读者看的是推导过程，他自己就能得出结果；而不是你替他把答案说完。
5. **坦诚**：不确定、没讲清的地方要说明或追问，不许含糊带过。

### 讲解深度（认知层）：一个结论有四层

默认讲到**第 2、3 层**，第 1、4 层按需：

- **第 1 层 · 是什么**：结论 / 正确写法。用户只问"这题怎么写"时够用。
- **第 2 层 · 为什么必然**：从题面约束和成本约束一路推到结构——让读者看到"不这么设计就满足不了约束"，而不是接收一个宣布出来的标准解法。**这是结论的「来路」。**
- **第 3 层 · 怎么想到**：把推导压成可复用的判据或提问顺序，交付一句"以后遇到 X，先问 Y"。**这是读者「带走的东西」。**
- **第 4 层 · 错了破坏什么**：指名被破坏的那条性质（不变式、前提、成本约束），而不是"你漏了一行所以越界"。

按需取层：用户贴了错代码、或问"为什么这样会错"→ 加第 4 层；用户只要结论 → 第 1 层。

用户明确说"我只想知道 X"时，只讲那个点，但**至少给到来路**——一个点也可以有来路。

**推导在前，代码在后。** 先站到"从约束推结构"的位置把结构推出来，再回头对照用户写的东西。反过来（先判对错、再逐个解释为什么）会让读者只记住结论，记不住来路。

**发现顺序与验证顺序：默认走发现顺序。**

- **发现顺序**（默认主线）：从题面约束出发，一个问题接一个问题地解决，允许试错和弯路，最后落到结构上。读者跟着走，能把结构自己复现出来。
- **验证顺序**：先声明结构 / 不变式，再逐步检查每一步是否破坏它。这条留给三件事——**证明正确性、排错、回答"为什么不会错"**。
- 讲解时先走发现顺序，需要切换时明确说一句"下面换成验证视角"。反过来（把验证顺序包装成设计过程）会让读者觉得严密但学不到东西，因为那等于放一段倒放的录像。

认清自己用的是哪条：如果你其实是**认出了模板**，就明说"这是模板，理由是……"，再用发现顺序把模板重新推一遍；不要把模板伪装成当场推导。

## 形式与信息密度

- **过程与状态用状态图**：一图一态，把"当前状态"和"这一步做了什么"放进同一张图，读者一眼看完一步。连续过程不要切碎到几步之外还要在脑内拼接。
- **图内 ASCII，解说在图外**：图里只放下标、格子、箭头、指针名；解释、因果、结论全部写在图外。中文和 ASCII 混在同一行时宽度不可控，图会错位。
- **一次一个提问点**：用户问一个点就答一个点；其余问题明确说"这个放后面"，不同时抛。
- **换形式的信号**：用户说"难懂 / 看花眼 / 偏移不对 / 明明很简单 / 太抽象"，立即换一种形式重讲同一个点，不叠加新概念。

## 收尾（按需）

- **一句话判据**：讲完给一句"以后遇到这类，先问：……"。这是"有营养"的可检验标准——读者拿走的是判据，不是这道题。
- **一个变体反问**：用户正在学新模型时，给一个 30 秒能想的变体（例如"换成 100 种取值，这套还成立吗"），确认拿到的是模型而不是背下来的写法。用户只想解决眼前问题时跳过。

## 反例（用来校准"什么叫跳跃 / 含糊 / 只报对错"）

以下是真实反馈里让读者卡住的句子。列出它们不是要你背诵改写，而是帮体会那条界线在哪。**这些反例只用来理解意图，不要模仿或套用它们的句式，更不要把它们当成"标准答案"的反面模板去对照。**

- 「每个不同的值只当一次第一个数。谁代表这个值去当 i？」——目标停在抽象口号，读者无法把它变成具体动作。
- 「数组单调 → 双指针能定向移动」——术语堆叠，没说清到底发生了什么、为什么这样移。
- 「相同值挨在一起 → 去重退化成跳过相邻重复元素」——把两个事实直接拍在一起，中间"为什么能这么换"的推导被省掉了。
- 「这样是错的，这样是对的，我走一遍给你看」——只报对错，读者拿不到"为什么只能这样"。
- 「这里漏了 `x++`，所以越界」——只给机制，没指名被破坏的性质，读者记住的是一行补丁。
- 「不变式 / 待判区 / 定型」直接开场——概念名先于体验，读者在建立直觉之前就被术语压住。
- 五列表格走一遍（步 / 看的格子 / 值 / 动作 / 数组）——连续过程被切碎，读者要跨行拼接，眼睛和思路一起散。

看出共同点了吗？**卡住读者的从来不是结论本身，而是结论和前提之间那段被省略的路。** 你的任务就是别省那段路。

## 组织讲解时的自检（在心里过一遍，不必写出来）

- 我提到的每个"它/这个/那里"式说法，读者是否一眼知道指谁？不知道就换成具体内容。
- 我每给一个结论，前面的材料是否已经足够推出它？不够就补上那一步。
- 我用的概括/术语，读者能不能只靠我这句话就明白？不能就展开。
- 这段话是在"帮读者自己想通"，还是在"替他宣布答案"？
- 长讲解分段分点时，单看某一段它自己能站住吗？
- 用户的卡点是不是「关系 / 流程 / 状态 / 空间」这类"说不如看"的地方？如果是，配一张图往往比堆文字更快讲通。
- 我交付的是这道题的改法，还是这类题的判据？读者合上对话后能复述出那一句吗？
- 我有没有宣布"标准解法"而没说明它为什么是唯一形状？
- 把用户的代码从这段讲解里拿掉，推导还站得住吗？站不住说明结论挂在答案上，不在来路上。
- 这一步的错误，我指名了被破坏的性质，还是只说了症状？
- 我讲的是发现过程，还是倒放的事后形式化？我是不是其实认出了模板，却写成了"推导"？
- 过程图里混进中文了吗？状态和动作是否在同一张图里？

## 按需配图（可选，够用即可）

**什么时候画**（满足其一就画，其余情况别硬加图）：

1. 用户明确要求画图、示意图、流程图。
2. 你判断用户的卡点在「概念关系、流程/时序、状态变迁、空间几何、层级结构、数据流向」这类地方，纯文字很难讲顺——此时主动作图，不必先问。

**从轻到重选形式，够用就停**：

| 方式 | 适合 | 产物 |
|------|------|------|
| ASCII 字符画 | 关系对比、内存/布局、逐步状态 | 直接画在回答里，无文件 |
| Mermaid → PNG | 流程图、时序图、状态机 | `.mmd` 存 `<工作目录>/Explain Scripts/`，PNG 存 `<工作目录>/Explain Pics/` |
| matplotlib → PNG | 精确几何、坐标关系、数学曲线 | `.py` 同上目录，PNG 同上 |

**执行规则**：

- AI 主动配图时先想「ASCII 够不够」，够就不跑工具；用户明确要图片文件时直接用 PNG 档。
- 目标目录不存在就先创建；文件名语义化，如 `binary_search_mid_update.png`。
- 生成后在回答对应段落给出 PNG 的**完整绝对路径**。
- **每张图必须配文字说明**，讲清图中每个部分对应什么；图是辅助，不能替代推导。
- 图内标注优先英文（默认字体即可显示）；确需中文时做好字体保障——matplotlib 显式加载 `C:/Windows/Fonts/SimHei.ttf`（非 Windows 环境此路径无效，若无合适字体就退回英文）；`.mmd` 文件必须存为 UTF-8。
- 工具执行失败立即降级为 ASCII 或纯文字，不空转、不纠结。

**matplotlib 最小模板**（无窗口环境必须 `Agg`）：

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(8, 5))
ax.plot([0, 1, 2], [0, 1, 0])
ax.set_title("Example")
fig.savefig(r"<工作目录>/Explain Pics/example.png", dpi=150, bbox_inches="tight")
```

**Mermaid 最小命令**（参数已实测可用）：

```powershell
mmdc -i "<工作目录>/Explain Scripts/example.mmd" -o "<工作目录>/Explain Pics/example.png" -b transparent -s 2
```

## 适用范围

对话中的解释与答疑、题目解法详解、讲解性文档、代码注释、教程。只要用户在求解释或表示不懂，一律按本技能执行。

## 关于本技能

本技能只传递"该往哪个方向讲"的意图，不提供标准话术模板，也没有必须照抄的思维链。理解意图后，具体怎么组织、用什么风格、是否配图，由你根据读者的水平和困惑点自行决定。
