# 已停在断点/异常上

## 适用场景
用户说"停住了"、"报错了"、"崩了"、"你看调用栈"——执行已暂停在断点或异常上。

## 流程

1. **检查现场** — `get_debug_context(max_stack_depth=20)`
   - 只读操作，任何时候调用都安全
   - 检查：当前位置（哪个文件+行号）、调用栈、局部变量

2. **深入检查** — `evaluate_expression("变量名或表达式")`
   - 仅在 `get_debug_context` 信息不足时使用

3. **决策**

   | 情况 | 做法 |
   |------|------|
   | 根因已明确 | 输出分析+修复方案，退出 |
   | 需要观察下一次触发 | `debug_control(continue)`，切到 `01-new-breakpoint.md` |
   | 需要逐步走 | 切到 `02-step-debug.md` |

## 注意事项
- 不要设新断点或调 `wait_next_hit`，除非你确定要继续观察后续执行
- 不要 continue，除非你明确决定让程序恢复
